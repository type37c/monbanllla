# monban MCP の口 v0(凍結)

日付: 2026-07-31
状態: **凍結**。凍結すべき API 三つのうち第三号(MCP ツール名)の本文。
ツール名 `monban.declare` は契約形式 v0(docs/contract_format_v0.md)で先行凍結済み —
この文書はその入出力と規則を固める。改訂は版上げ。

## 立て方

```sh
monban mcp            # banto ワークスペース(banto.toml のある場所)で立てる
```

- 輸送は **stdio**(改行区切りの JSON-RPC 2.0)。MCP 標準の stdio transport
- サーバー名は `monban`。ワークスペースはサーバーを立てた場所(`--root` で指定可)

## ツールは一つだけ

**`monban.declare`** — 完了の主張と証拠の提出。エージェントの唯一の入口。

| 引数 | 型 | 規則 |
|---|---|---|
| `seki` | string | 通ろうとする関の名前(契約 monban.toml に実在すること) |
| `title` | string | 主張の一文 |
| `evidence` | string[] | 成果物ファイルのパス(**1件以上必須**。三条一) |
| `actor` | string | 宣言者の名。**`agent:` で始まること**(この口はエージェント向け)。`agent:monban` は拒否(三条二) |

成功時の結果テキストにはイベント ID(64桁)が含まれる。エージェントは
その ID を人間に報せることしかできない — 改めは門番の仕事である。

## 存在させないもの(凍結)

- **改め(verify)に相当する MCP ツールは、将来の版でも存在させない。**
  エージェントに判を渡さないことが三条二の執行であり、この口の設計そのものである
- 台帳の読み・契約の書き換え・関の追加に相当するツールも置かない。
  門は狭いままにする

## 正直な限界(v0)

`actor` は記録されるが**認証されない**。エージェントが別の名を名乗ることは
この版では防げない(騙りは台帳に残り、後から突き合わせで露見する、という抑止まで)。
身元の証明は将来の版の課題として明示的に残す。
